# OAuth API compatibility — 2122
The receipt details route /v1.1/receipts/{transaction_id} requires receipts.read according to SumUp's published API documentation. The user configured transactions.history and user.profile_readonly, so use the single-transaction route /v2.1/merchants/{merchant_code}/transactions?transaction_code=... instead. Do not query transaction history or request write scopes. Produce a Mon Taxi Pro PDF based on verified reference, amount, timestamp and merchant; unavailable receipt-specific fields must stay empty. This change does not claim live OAuth verification. Do not deploy until device authorization, durable encrypted storage and callback are implemented and tested.
Sources: https://developer.sumup.com/api/receipts/get/ and https://developer.sumup.com/api/transactions/get/.
